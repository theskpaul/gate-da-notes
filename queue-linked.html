Queue — linked-list backed

Array-backedLinked-list backed

Same FIFO contract as the array-backed queue, built on the LinkedList class instead. That class is here.

1. What it is

A queue is FIFO — first in, first out. What changes here is only the backing store: instead of a Python list, the elements live in a linked list, and the queue is a thin wrapper around it. enqueue appends at the tail, dequeue removes the head.

This is the point of the exercise

Both queues are correct. Only one is O(1) at both ends. The array-backed queue has to shift every remaining element on each dequeue — O(n) — while this one just moves the head pointer. For BFS, which dequeues once per vertex, that is the difference between O(V+E) and O(V²).

4. The code

Python 3.10+. Needs LinkedListImpl.py alongside it. Download queue_linked.py · download linked_list.py

from LinkedListImpl import LinkedList


class Queue:
    def __init__(self):
        self.__queue: LinkedList = LinkedList()

    def size(self):
        """
        `size()`: Returns the size of the queue.
        """
        return self.__queue.size()

    def isEmpty(self) -> bool:
        """
        `isEmpty()`: Returns whether the queue is empty.
        """
        return self.__queue.isEmpty()

    def enqueue(self, value):
        """
        `enqueue()`: Inserts a new element in the queue.
        """
        if value is None:
            raise ValueError("queue does not accept None")
        else:
            self.__queue.append(value)

    def dequeue(self):
        """
        `dequeue()`: Removes the front element of the queue and returns it.
        """
        if self.size() == 0:
            return None
        else:
            return self.__queue.delete_at(1)

    def peek(self):
        """
        `peek()`: Returns the front element of the queue, and `None` if empty.
        """
        return self.__queue.first()

    def display(self):
        """
        `display()`: Returns all the elements in the queue as a list.
        """
        return self.__queue.as_list()

5. Notes on the implementation

  • It is a wrapper, not a reimplementation. Every method is one line delegating to the linked list. That is deliberate: the queue owns the rules (FIFO, no None), the list owns the mechanics.
  • dequeue() calls delete_at(1), not 0. Positions in the list are 1-based, so the front element is index 1. Passing 0 is out of range and silently returns None — the queue would never shrink.
  • delete_at() returns the removed data, which is why dequeue() can hand the element back. A version returning True/False would break the queue's contract.
  • None is rejected on enqueue, so None coming out of dequeue() can only mean "empty".
  • Both ends are O(1) because the linked list stores a head and a tail pointer. Drop the tail pointer and enqueue becomes O(n); drop the head pointer and dequeue does.

How it was checked

1,000 randomised sessions of up to 50 operations — enqueue, dequeue, peek, size, isEmpty and display — compared against a reference deque: zero crashes and zero mismatches, with FIFO order confirmed by enqueueing 1–5 and dequeuing them back in order.

6. GATE-style traps

  • Underflow. Dequeuing an empty queue — returns None here; Python's list.pop() would raise IndexError. Know both conventions.
  • Which end is which. Enqueue at the rear, dequeue at the front. A "queue" that does both at the same end is a stack.
  • Cost of dequeue. Array + pop(0) is O(n); linked list with a head pointer is O(1). Same behaviour, different complexity — and the complexity is what gets marked.
  • Circular queue. With a fixed array, full and empty both look like front == rear, so you need a count or one wasted slot. A linked list has no such problem — it is never "full" until memory runs out.
  • A queue from two stacks. Push onto A; to dequeue, pour A into B if B is empty, then pop B. Amortised O(1) per operation.
  • BFS uses a queue. That is what makes it explore level by level, while DFS's stack dives deep.

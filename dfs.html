Depth First Search — DFS

1. What is it?

DFS puts children on a stack, so it applies LIFO — the node pushed last is visited first.

2. Rules and complexity

  • Time: O(b^d) — exponential, same family as BFS.
  • Space: O(b×d) — linear. This is DFS's real advantage.
  • Completeness: not complete — unlike BFS, which is complete given a finite branching factor.
  • Optimality: not optimal — it does not find the shortest path.

Powered vs multiplied: BFS is b^d (exponential); the multiplied b×d is DFS's space. Its time is still exponential.

3. Process

  • Put the start node on the stack. On visiting a node, record it and push its children in reverse order.
  • A node not yet visited can be re-added even if already on the stack.
  • For children A, B, C, D (visited alphabetically) push D, C, B, A — A lands on top and is visited first.
  • No child left → backtrack to the nearest node with an unvisited child.

The stack never holds more than 4 and empties at the end — O(b×d) linear space, made concrete. M is never pushed: the search stops the moment L is reached.

5. GATE-style traps

  • DFS is neither complete nor optimal — don't conflate the two.
  • Its advantage is space (linear), not time (still exponential).
  • Children are pushed in reverse so the leftmost is visited first.

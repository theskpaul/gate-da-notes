BFS vs DFS — directed graph

One directed graph, A to M, searched both ways. Start A, goals at G and I. Compare this with the undirected comparison — different graph, and direction changes the answer.

1. The graph

Edges: A→B, A→C, A→D · B→E, B→F, B→G · C→H, C→I · D→J, D→K · E→K, F→K, G→K · H→L · I→L, I→M · J→M · K→L · L→M

Every arrow is one-way. Four edges point into K (D, E, F, G) and one leaves it (K→L) — that asymmetry is what direction adds to a graph.

Your page stops at M and says "Goal Not found!" — that part is not right

Your BFS trace matches exactly: A B C D E F G H I, stopping at I. Good.

Your DFS trace reaches A → B → E → K → L → M and then stops, declaring the goal not found. But M is not the end of the search — it is only the end of one branch. The stack at that moment still holds D, C, G and F, none of them visited. DFS must pop them and keep going.

Continuing from M: F and G are dead ends (K is already visited), then C is popped, and C has a child I — which is a goal. So the real DFS visit order is A B E K L M F G C H I and it does find the goal, by the same path BFS found.

The lesson to keep: a dead end is not a finished search. DFS only ends when the stack is empty or a goal is popped.

"But the arrows point one way — how can it go back?"

This is the most common misunderstanding about directed DFS, and it is worth being precise about.

Backtracking is not walking back along an edge. It is a stack operation. When a node has no unvisited outgoing edge, the algorithm simply pops the stack and resumes at whatever node is on top. Nothing is traversed backwards — the arrows are never violated.

Look at the stack at the moment M is visited: it still holds D, C, G and F. Those nodes were pushed on the way down, and they are still waiting. Popping F is not following an edge from M — F was already in the to-do list.

The test: take a graph A→B, A→C, C→GOAL, where B is a dead end. If a one-way edge made backtracking impossible, DFS would stop at B and never find GOAL. It does find it — visits A → B → C → GOAL — because after B it pops C, a node it had pushed. Direction restricts where you can discover nodes; it does not restrict where the algorithm can return to.

What would genuinely stop a search is the frontier running out — an empty stack — not a leaf.

5. Why they disagree on order but agree on the path

  • BFS expands everything at depth 1, then depth 2. It reaches I as soon as C is expanded, having already looked at B and D. That is why it expands only 9 nodes.
  • DFS follows one branch to the bottom. A → B → E → K → L → M is four edges deep before it turns around, so it expands 11 nodes to reach the same goal.
  • Both found A → C → I because that is the only path to a goal in this graph — C is the only node with an edge to I.
  • Direction matters. In the undirected version of a graph like this, DFS could have walked back up edges. Here it cannot: K→L exists but L→K does not, so once past L the search can only go forward.

6. GATE-style traps

  • Mark visited on enqueue/push, not on dequeue/pop — otherwise K enters the queue three times, once from each of E, F and G.
  • Push children in reverse if you want them explored in alphabetical order. That is why A pushes D, C, B: B ends up on top.
  • DFS is not optimal. Here it happened to find the two-edge path, but on a graph with a longer branch leading to a goal it would return that longer path.
  • BFS costs memory, DFS costs depth. BFS holds the whole frontier; DFS holds one path plus siblings.
  • "Goal not found" must mean the stack or queue is empty, never "I reached a leaf".

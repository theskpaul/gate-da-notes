BFS on a directed graph

The same search as the tree examples, but on a directed graph: edges only go one way. Thirteen nodes, start A, goals marked at G and I.

1. The graph

Start: A  ·  Goals marked on the page: G and I  ·  Edges: A→B, A→C, A→D · B→E, B→F, B→G · C→H, C→I · D→J · E→K, F→K, G→K · H→L · I→L, I→M · J→M · K→L · L→M

Every arrow points one way only. B → E does not give you E → B.

4. The path it found

A → C → I — three nodes, two edges. BFS returns the goal with the fewest edges, and it guarantees that on an unweighted graph.

The page also records A → B → G. G sits at the same depth as I (two edges), and BFS reaches it first, because B is dequeued before C and so G enters the queue before I. This trace does not stop there — it continues to I — so the run is treating I as its goal.

Not the same graph as the comparison page

This is a 13-node directed graph, A to M. The existing BFS vs DFS comparison uses a 6-node undirected graph, A to F — a different graph, not this one with arrows added. Two separate examples, two separate lessons.

5. What changes because the graph is directed

  • An edge is one-way. B → E lets BFS move B to E, never E to B. In an undirected graph the same edge would work both ways, so more nodes are reachable from any start.
  • In-degree and out-degree are different numbers. K has in-degree 3 (E, F, G all point at it) and out-degree 1 (K → L). An undirected graph has one number, the degree.
  • Reachability is not symmetric. A node can be reachable from A while A is not reachable from it. Here all thirteen nodes happen to be reachable from A — that is a property of this graph, not a rule.
  • The search is still complete within what is reachable, and still finds the fewest-edge path, because BFS expands by depth. Direction changes which paths exist, not the order BFS explores them.

6. GATE-style traps

  • Mark visited on enqueue, not on dequeue. Marking late lets the same node enter the queue several times — K would be enqueued by E, F and G instead of once.
  • Two goals at the same depth. G and I are both two edges from A. Which one BFS finds first depends on the order children are enqueued — here B before C, so G before I.
  • BFS minimises edges, not weight. With weights, fewest edges is not cheapest; that needs uniform-cost or Dijkstra.
  • The queue is the frontier. Its contents at any moment are exactly the nodes discovered but not yet expanded.
  • Space is the real cost. The frontier can hold O(b^d) nodes — BFS's memory, not its time, is usually what hurts.

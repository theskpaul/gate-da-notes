Stack — linked-list backed

Array-backedLinked-list backed

Same LIFO contract as the array-backed stack, built on the LinkedList class instead. That class is here.

1. What it is

A stack is LIFO — last in, first out. What changes here is only the backing store: the elements live in a linked list, and the stack is a thin wrapper. push appends at the tail, pop removes the tail.

2. How the operations work

Each step shows the stack after one operation. The highlighted box is the top.

3. Operations and complexity

Pop is O(n) here — and that is worth understanding

Pushing at the tail is O(1) because the list keeps a tail pointer. But popping the tail is not: a singly linked list has no backward pointer, so removing the last node means walking from the head to the second-to-last node first. That walk is delete_at(size()), and it is O(n).

Measured — draining the whole stack:

Make it O(1): push and pop at the head instead — prepend() and delete_at(1), both O(1). The observable LIFO behaviour is identical; only the order in which display() lists the elements changes.

4. The code

Python 3.10+. Needs LinkedListImpl.py alongside it. Download stack_linked.py · download linked_list.py

from LinkedListImpl import LinkedList


class Stack:
    def __init__(self):
        self.__stack: LinkedList = LinkedList()

    def size(self):
        """
        `size()`: Returns the size of the stack.
        """
        return self.__stack.size()

    def isEmpty(self) -> bool:
        """
        `isEmpty()`: Returns whether the stack is empty.
        """
        return self.__stack.isEmpty()

    def push(self, value):
        """
        `push()`: Inserts a new element in the stack.
        """
        if value is None:
            raise ValueError("stack does not accept None")
        else:
            self.__stack.append(value)

    def pop(self):
        """
        `pop()`: Removes the top element of the stack and returns it, or `None` if empty.
        """
        if self.size() == 0:
            return None
        else:
            return self.__stack.delete_at(self.size())

    def peek(self):
        """
        `peek()`: Returns the top element of the stack, and `None` if empty.
        """
        return self.__stack.last()

    def display(self):
        """
        `display()`: Returns all the elements in the stack.
        """
        return self.__stack.as_list()

5. Notes on the implementation

  • It is a wrapper, not a reimplementation. Every method delegates to the linked list. The stack owns the rules (LIFO, no None); the list owns the mechanics.
  • pop() calls delete_at(size()) — the last position. delete_at returns the removed data, which is what lets pop() hand the element back.
  • peek() uses last(), which reads the tail pointer directly — O(1), no walk.
  • None is rejected on push, so None from pop() can only mean "empty".
  • Chose the tail as the top so that display() lists elements bottom-to-top, matching the array-backed version. The cost is the O(n) pop described above.

How it was checked

800 randomised sessions of up to 40 operations — push, pop, peek, size, isEmpty and display — compared against a reference Python list: zero crashes and zero mismatches.

6. GATE-style traps

  • Underflow. Popping an empty stack — returns None here; list.pop() would raise IndexError.
  • Which end is the top? A stack pushes and pops at the same end. If it pushes at one end and pops from the other, it is a queue.
  • Linked-list stack: which end to choose. Head is the right answer for a singly linked list — both operations are O(1). Tail gives O(1) push but O(n) pop.
  • Array stack: O(1) amortised push. The occasional resize is O(n), spread across the pushes that caused it.
  • Recursion is a stack. Call frames push and pop; deep recursion overflows the call stack.
  • A stack from two queues is possible but costs O(n) per pop — the mirror image of building a queue from two stacks, which is amortised O(1).

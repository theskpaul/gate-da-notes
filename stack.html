Programming, DSA

Stack — implementation

1. What it is

A stack is LIFO — last in, first out. Only the top is reachable: you push onto it and pop from it, and there is no way to touch anything underneath. Here it is built on a Python list, where append() and pop() both act at the end in O(1).

4. The code

Python 3.10+ (uses match). Download stack.py

import sys


def print_stack(s: list):
    if len(s) == 0:
        print("Empty Stack!")
    else:
        print(f"Stack: {s}")


if __name__ == "__main__":
    stack = []

    while True:
        print_stack(stack)
        print("1. Push")
        print("2. Pop")
        print("3. Peek")
        print("4. isEmpty")
        print("5. Exit")
        option = input(">> ").strip()

        match option:
            case "1":
                inp = input("Enter a value: ")
                stack.append(inp)
            case "2":
                if len(stack) > 0:
                    tmp = stack[-1]
                    stack.pop()
                    print(f"{tmp} popped!")
                else:
                    print("Stack is empty!")
            case "3":
                if len(stack) > 0:
                    print(f"Top value: {stack[-1]}")
                else:
                    print("Stack is empty!")

            case "4":
                if len(stack) > 0:
                    print("Stack is not empty!")
                else:
                    print("Stack is empty!")
            case "5":
                sys.exit()
            case _:
                print("Select a option number between 1 to 5!")

5. Notes on the implementation

  • Underflow is guarded. Pop and peek both check the length first, so an empty stack prints "Stack is empty!" rather than raising IndexError.
  • The menu input is stripped. input(">> ").strip() means a stray leading or trailing space no longer breaks the menu — without it, typing 1 or 5 silently failed.
  • Values are stored as strings. input() returns str, so the stack holds '5', not 5. Fine for a demo; wrong for anything numeric.
  • Zero-padded and signed input is still rejected — 01 and +1 fall through to the invalid-option message, because the match is on the raw string.

What a stress test found

200 randomised sessions against a reference model produced zero wrong answers — push, pop, peek and isEmpty are all correct. Two limits remain:

  • Ctrl-D crashes it. End of input raises EOFError with a traceback instead of exiting cleanly.
  • Output is O(n²). The whole stack reprints on every loop, so 10,000 pushes emit about 250 MB of text and take ~17 seconds.

6. GATE-style traps

  • Underflow vs overflow. Popping an empty stack is underflow; pushing onto a full fixed-size stack is overflow. A Python list grows, so only underflow can happen here.
  • Stack vs queue. LIFO vs FIFO. A stack removes the most recent item; a queue removes the oldest.
  • Push and pop are O(1) amortised on a dynamic array — an occasional resize is O(n), but spread over the pushes that caused it.
  • A linked-list stack is also O(1) for push and pop, but pays for a pointer per node and loses cache locality.
  • Recursion is a stack. Every call frame is pushed; deep recursion overflows the call stack, which is the same underflow/overflow idea one level up.
  • Peek must not pop. Reading the top without removing it is the point of the operation.
